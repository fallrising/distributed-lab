# ADR-0004 有界活性風險查核

- 狀態：方法、結果與最終文件均已由非作者審查通過。
- desk：T-0458；技術任務：issue #27。
- 基準：產品 `e4e538654f5dd821683f02538cc10c10996764e9`，specs `0f0f4dcf471c1f7ccc381ceeb5eda99c609e98e5`。

## 決定

針對 ADR-0002 E3 的兩個未實測組態做一輪有限外部輸入搜尋，保留原 AC-QLT-02 的資料與期限。這份紀錄歸檔執行前已寫在卡及 issue #27 的方案；不改共識規則或重新定義驗收。

1. 使用完整五成員集合分割的 52 種組合，4–8 個初始 partition／heal 事件。定向候選一次只改一個事件、插入或刪除一個事件（2–8 個），所有 tick 都在原故障前綴內。
2. 固定 audit seed 45801、beam width 4、初始每個 bound 512 個候選。前綴 bound 2/6 分別搜尋 H1/H2，每個 cell 最多 767 次定向嘗試；保留 parent 的傳遞種子及讀取閘道。完整輸入簽章包含 bound、腳本、策略種子與閘道。
3. 最多 4092 個候選名額，另預留四次重播，總上限 4096。重複輸入直接排除，不補足至上限；有限計畫結束即停，不追加種子。
4. H1 區分 B 唯一最新日誌與客戶端是否仍未完成，後者只是子分類。H2 區分日誌層次、非嚴格平手、實際同任期拒票退避；role/term 轉移與相應 RequestVote 必須一致。不能用 tick 末日誌冒充訊息處理前瞬間的日誌。
5. 窗口與操作時刻、結果及期限全部從固定資料讀取。只用公開 Experiment 介面及允許外部前綴，不注入內部狀態。第一個真實期限、值或安全違反即停並保留原失敗；不符合前提、檢查未判定或重播不一致也停止，不當作通過。

## 證據與限制

執行前固定兩個工具來源的 SHA-256、原始資料 digest、基準 SHA 與配置，保存在結果索引。候選的角色／日誌觀察、判定及完整錄製留在本次臨時輸出；repo 只保留精簡摘要、代表輸入、digest 及重建方式。

52 種分割均被使用，只說明這個離散群組集合的覆蓋，沒有窮舉事件次序、時刻或傳遞排程。定向排名也可能造成讀取閘道覆蓋不均，必須報告實際分布。找不到目標組態不證明它不可達，沒有找到違反也不表示 ADR-0002 的兩項風險已解決。

本輪是參考實作品質查核。正式模型比較另外需要相同起點、整套配置、主預算、修復額度與獨立案例；不能追溯將 Claude M1/M2 與 Codex 多 agent M3 的不同工作當作公平對照。
