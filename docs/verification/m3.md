## 驗證方式

`npm ci && npm run typecheck && npm test`，CI 另跑 `npm run verify-source`。本次 Cloud 環境的預設隔離 runner 只回報檔案數，因此本機另以 Node 22.23.1 執行：

```sh
node --test --experimental-test-isolation=none 'test/**/*.test.ts'
```

這不修改或跳過任何測試；個別測試結果及 CI run 連結留在實作 PR。來源核對若需要環境代理，使用 `node --use-env-proxy scripts/verify-source.ts`，驗證腳本不變。

AC 先於實作寫入。初次型別檢查與三個新 AC 檔因缺少 `runSnapshotCase` 等 API 失敗（0 pass、3 fail、0 skip），之後才實作。沒有提交失敗狀態；原 AC 斷言與策略不變，只有 helper 的一個變數補明確型別。

## 新增 AC

**AC-RUL-07**
- 固定情境每個 stage 都使用資料的原期限，沒有額外 settle 時間。
- 驗證 ABCD 確實壓縮詳細前綴、B 的穩定快照跨 crash/restart 保存，以及 E 在恢復期間透過實際 InstallSnapshot 與日誌追上。
- heal 後下一 tick 立即經 E 讀取，不能先等待恢復再送讀取；成功回覆與 E 套用新讀取都必須在原期限內成立。

**AC-RUL-08**
- 原請求重試經已重啟的 B，必須收到新送出的叢集回覆；不能以原本完成的 outcome 充數。
- 快照保留原意圖、結果與單次邏輯效果，新讀取不回退到舊寫值。

**AC-QLT-04**
- 每個策略同時跑有／無壓縮配對，比較身分、結果、新讀值與最終已確認 KV；不比較資料允許不同的事件細節與時刻。
- 快照流程逐 stage 重播，快照之後的反事實分支保留前綴與基準實驗。

三條 AC 都使用原有 `timingStrategies` 的 235 種固定策略：min、max、32 種依目的地延遲、資料的重播種子與另外 200 個固定種子。這是抽樣，不能當作窮舉證明。

## 限制
